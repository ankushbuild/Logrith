-------------------------------------------------------------
KEYWORD STRATEGY (NEW REQUIREMENT):
-------------------------------------------------------------
Every tool post must target LOW-COMPETITION keyword variants, not
just the obvious high-volume head term. Competitors (SmallSEOTools,
iLovePDF, FreeFormatter, Convertio, TinyWow, etc.) already dominate
the broad head terms — ranking against them directly on something
like "image compressor" alone is unrealistic early on. Instead, each
post's title, headers, and meta should incorporate specific,
longer-tail, lower-competition phrasings alongside the head term:
- "[tool] without sign up" / "[tool] no email required"
- "[tool] for [specific file type/use case]" (e.g. "compress PNG
  for WordPress", "resize photo for passport")
- "how to [task] without [common friction point]" (e.g. "without
  losing quality", "without installing software")
- "[tool] vs [specific competitor]" comparison-intent phrasing
- Question-form long-tail ("how many pages is 1500 words", "what is
  a good typing speed")
- "free [tool] no watermark" / "free [tool] unlimited" where
  genuinely true and relevant
Choose these per-tool based on realistic search intent for that
specific tool, not a generic template applied blindly. Weave
naturally into meta title/description, H2/H3 headers, and the
comparison section — never keyword-stuff unnaturally.

   - Open Graph + Twitter Card tags

     BreadcrumbList, FAQPage where a Q&A section exists)
   - Proper heading hierarchy (H1 once, H2/H3 structured sections)
   - Internal linking to the actual tool + related tools/blogs

3. COMPETITOR RESEARCH PER TOOL: For each tool's blog post, research
   what competitor tools/sites offer for that same tool category
   (e.g., for "word counter" blog — look at how other word-counter
   tools/sites position themselves). Use this to inform a genuine

4. REQUIRED SECTIONS PER BLOG POST (in reasonable order):
   a. Hero section with tool name, compelling intro, and a hero
      action button (see button logic below)
   b. Full description of what the tool does and why it matters
   c. "How to Use" step-by-step section (numbered steps)
   d. Comparison section — Logrith's tool vs typical competitor
      tools in that space (honest, specific, not just marketing fluff)
   e. FAQ / Q&A section (genuine common questions, not filler)
   f. Article/deep-dive section with real substance (this is where
      most of the 3-4k word count comes from — real explanations,
      use cases, background, technical or practical depth depending
      on tool type)
   g. Related tools section (internal links to other relevant tools)
   h. Standard footer/nav (same site-wide components)

5. HERO BUTTON LOGIC — CRITICAL, TOOL-SPECIFIC:
   The hero section's call-to-action button text and behavior must
   match what the underlying tool actually does:
   - If the tool is an UPLOAD-based tool (e.g., image compressor,
     PDF merge, photo resizer) → button says "Upload" (or similar,
     e.g. "Upload Image", "Upload PDF") and clicking it redirects
     straight to the actual tool page.
   - If the tool is a GENERATE-based tool (e.g., password generator,
     QR generator, barcode generator, random quote generator) →
     button says "Generate" (or similar, e.g. "Generate Password")
     and clicking it redirects straight to the actual tool page.
   - If the tool is a CONVERT-based tool (e.g., YAML to JSON, unit
     converter, currency converter) → button says "Convert" (or
     similar, e.g. "Convert Now") and redirects to the tool page.
   - For other tool types (calculators, checkers, formatters,
     translators, lookups) → use the most natural matching verb
     for that tool's actual primary action (e.g. "Calculate",
     "Check", "Format", "Translate", "Look Up") — always redirecting
     directly to the real tool page on click.
   RULE OF THUMB: the button's verb must always match the tool's
   real primary action, and it must always link directly to the
   live tool (not just to another blog or generic page).

6. NO SKIPPING CONTENT: Every element the person asked for (SEO,
   title, description, competitor comparison, FAQ, article, how-to,
   hero button logic) must appear on every single one of the 100
   tool posts — not just a sample of them. Consistency across all
   100 is mandatory.
